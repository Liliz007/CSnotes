# 2. 计算机网络的定义与分类

## 2.1 定义

计算机网络：将地理位置不同的、具有独立功能的多个计算机系统，通过通信设备和线路连接起来，在网络软件（网络协议等）的管理协调下，实现资源共享和信息传递的系统。

# 4. 数据交换方式

## 电路交换

直接用电线连接。如电话和电话交换机的联通

交换就是按某种方式动态分配传输线路的资源

电路交换的步骤：
1. 建立连接：分配独有通信资源
2. 通话：一直占用资源
3. 释放连接：归还通信资源

## 分组交换

不用事先建立连接，交换机收到包后先缓存，再选择空闲线路发送

将报文划分为小段并加上首部，首部中包含该分组的目标地址。收到后去掉首部并拼接
* 发送方：构造分组并发送
* 路由器：缓存分组并转发
* 接收方：接受分组并还原报文

分组乱序会在后面介绍。

## 报文交换

也采用缓存转发机制，但对报文大小无限制。从而需要各节点交换机都具有较大空间

主要用于早期的电报

## 为何要分层？

物理层问题：
* 采用什么传输介质？
* 采用怎样的物理接口？
* 使用什么信号表示比特0和1？

数据链路层问题：
* 如何标识网络中的各主机？（主机编址问题）
* 如何从信号中区分出地址和数据？
* 如何协调总线争用问题

网络层：
* 如何标识各网络及其中主机？（网络和主机共同编址问题）
* 路由器如何转发分组、选择路径？

运输层：
* 如何解决进程之间基于网络通信的问题（信号交给哪个进程处理？）
* 出现传输错误？（误码、丢包）

应用层：
* 通过应用进程间的交互来完成特定网络应用

![](../image/2026-09-18-21-21-30.png)

## 一个简单的分层工作流程举例

假设在浏览器里访问一个网页，浏览器生成一个 HTTP 请求报文。

这个报文要从你的电脑传到服务器，需要经过协议栈的层层封装：

```
应用层：   [ HTTP 报文 ]    //1
传输层：   [ TCP 首部 ][ HTTP 报文 ] (=TCP报文段)   //2
网络层：   [ IP 首部 ][ TCP 首部 ][ HTTP 报文 ](=IP数据报)     //3
数据链路层：[ 帧首部 ][ IP 首部 ][ TCP 首部 ][ HTTP 报文 ][ 帧尾部 ](=)   //4
物理层：   101011010...（比特流）   //5
```

* TCP首部：主要是标志发送/接收方分别是哪个应用进程，检测传输过程中是否出错
* IP首部：标志源主机和目的主机等
* 帧首尾：相邻节点传输，即在同一段链路（如以太网）上把帧从一个网卡送到另一个网卡
  * 帧尾部有帧校验序列FCS，用于检测传输中是否出错
  * 网卡负责相邻节点的传输，做的是物理层和链路层的活儿

## 一些专用术语

### 实体，entity

实体：任何可发送或接收信息的硬件或软件进程

对等实体：收发双方位于相同层次的实体

![](../image/2026-09-18-21-49-25.png)

### 协议，protocol

协议：控制两个对等实体进行逻辑通信的规则的集合

**之所以说是逻辑通信，是因为这种通信其实并不存在，只是用来单拎出一层讨论**

![](../image/2026-09-18-21-50-45.png)

三要素：语法，语义，同步
* 语法：定义交换信息的格式（有哪些字段及其顺序）
* 语义：定义收发双方所要完成的操作
* 同步：定义收发双方的时序关系。如下图

![](../image/2026-09-18-21-54-30.png)

### 服务

服务：
* 在协议的控制下，两个对等实体间的逻辑通信，使得本层能向上层提供服务。
* 要实现本层协议需要依赖下层的服务
* 协议是水平的，服务是垂直的
* 下层的协议对上层的实体是透明的（不可见的）

![](../image/2026-09-18-21-57-10.png)

服务访问点：在同一系统中相邻两层的实体交换信息的逻辑接口称为服务访问点（SAP），它被用于区分不同的服务类型
  * 怎么个区分？

服务原语：上层要使用下层所提供的服务，必须通过与下层交换一些命令，这就是服务原语

协议数据单元(PDU)：同一系统内对等层之间交换的数据包

![](../image/2026-09-18-22-00-54.png)

服务数据单元(SDU)：同一系统内层与层之间交换的数据包

注意：
* SDU：本层从上层收到的数据，是要服务的数据。
* PDU：本层加上首部/尾部后，实际发出去的数据单元。
* 本层PDU = 下层传来的SDU + 本层首尾部
* 他俩不一定是一对一关系：
  * 多SDU对一PDU：多个小 SDU 单独发，首部开销太大
  * 反之，下层SDU太大，要拆成多个PDU分开发。

# 8. 常用指标

速率，带宽，吞吐量，时延，时延带宽积，往返时间，利用率，丢包率

**速率：也称比特率，数据率**

注意速率单位和数据量单位的进率关系
![](../image/2026-09-16-16-49-14.png)

**带宽：单位时间内能传输的最高数据量**

单位与速率相同，但含义不太一样。表示的是一种能力。

数据实际传输速率受多个因素影响：主机接口速率，线路带宽，交换机或路由器的接口速率

数据传送速率 = min[ 主机接口速率，线路带宽，交换机或路由器的接口速率 ]（木桶效应）

**吞吐量：单位时间内通过某个网络或接口的实际数据量**

**时延：数据从网络的一端传送到另一端所耗费的时间，也称为延迟或迟延**
* 发送时延：
  * 公式：发送时延=分组长度(b)/发送速率(b/s)。
  * 由发送速率、信道带宽、接口速率共同决定，木桶效应
* 传播时延：链路上用时。
  * 公式：传播时延=信道长度(m)/传播速率(m/s)
* 处理时延：存储转发用时，难以计算

![](../image/2026-09-18-20-45-24.png)

![](../image/2026-09-16-16-58-17.png)

排队时延(queueing latency)和处理时延(processing latency)，统称为处理时延，不方便计算。

**时延带宽积：传播时延与带宽的乘积**

![](../image/2026-09-16-17-00-17.png)

从发送方开始发送数据，到第一个比特到达接收方这段时间里，发送方一共能往链路上“注入”多少个比特。也就是拿bit来描述链路长度

**往返时间**(round trip time,RTT)：从源主机发送开始，到收到目标主机的确认信号的时间

**利用率：分为信道利用率和网络利用率**
![](../image/2026-09-16-17-05-42.png)

当网络的通信量较少时，产生的时延并不大，但在网络通信量不断增大时，分组在交换节点（路由器或交换机）中的*排队时延*会随之增大，因此网络引起的时延就会增大

**丢包率：分组丢失率，一定时间内传输中丢失包数量与总包数量之比**

分为接口 / 节点 / 链路 / 路径 / 网络丢包率
分组丢失主要有以下两种情况：
* 分组在传输过程中出现误码，被传输路径中的节点交换机（例如路由器）或目的主机检测出误码而丢弃
* 节点交换机根据丢弃策略主动丢弃分组(新的分组来到一个缓冲区满的节点会被丢弃。但一般不会允许装满，而会主动丢弃)

丢包率可以反映网络的拥塞情况：
* 无拥塞时路径丢包率为 0
* 轻度拥塞时路径丢包率为 1%~4%
* 严重拥塞时路径丢包率为 5%~15%
