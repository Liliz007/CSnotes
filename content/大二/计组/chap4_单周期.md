# 处理器

## 1. 单周期CPU

### 1.1 概述

* review: CPU性能衡量公式

![4-1](../image/2025-11-06-11-23-33.png)

* **CPI = Cycles per Instruction**
* **Clock Cycle Time** : 每个周期具体用时多长，这取决于电路的实现，是我们设计的直接产物。

我们的使命，就是在保证功能正确的前提下，疯狂地压榨CPI和时钟周期时间。然而，这两者往往是相互矛盾的。单周期CPU，CPI可以做到1，但其时钟周期会被最慢的指令拖累得非常长。
一个复杂的设计（比如后续要学的流水线处理器），时钟周期可以很短，但可能会因为各种暂停（Hazard）导致CPI上升。

**处理器生命周期五部分：**
1. 取值：Instruction Fetch,IF
2. 译码：Instruction Decode,ID
3. 执行：Execute,Ex
4. 访存：Memory,Mem
5. 写回：Write-Back,WB

**指令执行的overview**

1. 所有指令共有的前两步:

    **IF:** 从存储器I_mem中取指令

    **ID:** 解码并读取寄存器

2. 后续步骤取决于指令类型:

    **Memory-reference:** 访存指令

    **Arithmetic-logical:** 算术逻辑指令

    **Branches:** 分支指令

3. ALU的用途:
   * 计算算术结果
   * 计算访存地址（ld,sd指令）
   * 进行分支比较（beq,bne之类）

4. 最后:
    访存，指令访问数据存储器load or store
    更新PC为下一条指令地址（PC+4）或分支目标地址

### 1.2 设计的元件

无记忆的“计算者”与有记忆的“存储者”

#### 1.2.1 组合逻辑原件

输出仅与输入有关，与时间、状态无关，**电路延迟是他们唯一的物理属性**

* ALU
* Adder：用于计算PC+4和分支目标地址
* MUX：当数据来源不唯一时，就要用到MUX

#### 1.2.2 时序逻辑元件

它们的输出不仅依赖于当前输入，更依赖于内部存储的状态。它们是系统状态的载体。

* Reg：最基本的存储单元。它有一个数据输入D，一个数据输出Q，以及一个时钟输入Clk。只有在时钟的上升沿到来时，Q的值才会更新为D的值。
* 带写使能的Reg：当clk上升沿时RegWrite处于高电平，才更新reg的值。reg file和PC的设计都基于此
* Memory：它有一个地址输入，一个数据输入（用于写），一个数据输出（用于读），以及读/写控制信号。

### 1.3 时钟同步

时钟信号相当于总指挥，使得各个信号有序活动。

我们的工作模式：
  * 在一个时钟周期的开始（上升沿），数据从一个状态元件（如PC，寄存器堆）中被读出。
  * 这些数据流经一系列组合逻辑（如ALU，MUX），进行计算和选择。这是一个纯粹的物理传播过程，需要时间。
  * 在下一个时钟周期的上升沿到来之前，组合逻辑的输出必须稳定下来，并准备好被写入下一个状态元件。
  * 在下一个上升沿，新的计算结果被锁存到目标状态元件中。

![4-4](../image/2025-11-06-19-34-34.png)

从而有如下约束：

$$
T_{clk} \ge T_{state\_read}+T_{critical}+T_{setup}
$$

* $T_{clk}$是cycle time，$T_{setup}$是下一个上升沿到来前，数据必须保持稳定的时间。$T_{state\_read}$是从I_mem中读取指令的时间。
* 若中间的组合逻辑越复杂，关键路径延迟就越长，$T_{clk}$就越长，CPU性能就越差。

### 1.4 各阶段分工介绍

**review** 指令format

![4-5](../image/2025-11-06-19-39-58.png)

#### （1）取指(IF)

**任务：** 
* 根据PC寄存器的地址，到指令存储器中取指令
* 计算出下一条指令的地址 PC+4。

**部件：** 
* PC: 是一个64bit的寄存器，程序计数器，存放下一条指令地址。

* Instruction Memory: 指令存储器，根据输入的地址输出该地址的32bit指令。

* Adder: 加法器，用于计算 PC + 4（下一条顺序指令地址）。（在IF阶段就把PC+4更新回去了，从流水线那也可以看出来）

**连接：**

![4-6](../image/2025-11-06-19-45-08.png)

#### （2）译码(ID)

**任务：**
* 生成控制信号
* 读取源寄存器并输出
* 生成立即数；扩展branch类指令的偏移量

**元件：**
* Control Unit
* ImmGen
* Reg File

#### (3)执行(Ex)

**任务：** 进行ALU运算，得到算数、逻辑结果
* 对于R型指令：ALU执行相应的算数逻辑运算，并输出结果
* 对于访存指令：ALU计算base addr和Imm的和，得到数据的真正地址
* 对于分支指令：ALU将两源操作数相减，根据结果是否为0，判断两数是否相等

#### (4)访存+写回(Mem，WB)

**任务**：
* 访存：对于访存指令，ALU计算基地址和立即数的和，得到真正地址并输入data_mem；然后ld从data_mem读取数据并输出，sd向数据存储器写入数据。R型在此阶段不做事。
* 写回：R型指令将运算结果写回rd寄存器，ld指令将存储器数据写回寄存器堆

* IF阶段同时还负责计算PC+4.
* 注意ID阶段做三件事：生成ctrl信号，读寄存器，生成立即数
* jump和branch的计算结果在MEM阶段更新到PC寄存器中。（在流水线中会导致3个时钟周期的控制冒险，若预测错误则需将后续三条指令冲刷掉）
  
### 1.5 RISC-V数据通路的构建

我们从最简单的R-Type开始，逐步丰富其功能。

#### 1.5.1 R-type指令的DataPath

    add x9,x20,x21

**任务：** 从32bit指令中解码出rs1,rs2,rd，再从寄存器堆中读出rs1,rs2内的值，送入ALU内进行加法后，将值写回rd中

**元件：** 寄存器堆，ALU

![4-7](../image/2025-11-06-19-50-40.png)

* read reg1,read reg2输入rs1和rs2的地址，write reg输入rd的地址
* write data输入要写入rd的值
* RegWrite是控制信号，当其为1时，允许写操作发生。
* 寄存器堆的两个输出是从rs1和2中读出的数据，要送到ALU中。

#### 1.5.2 引入Mem操作(ld,sd)

    ld x9,200(x1)

**任务：** 

* 读取 x1 中的基址
* 将指令中的 12bit 立即数（偏移量）进行符号扩展至 64bits
* 用ALU计算 (x1)+200 得到内存地址
* 访问内存（Data Memory），读出数据
* 将读出的数据写回 x9

**连接图及讲解：**

![4-8](../image/2025-11-06-20-02-47.png)

* ImmGen是用来对imm做符号扩展的
* 左侧MUX用来选择ALU的第二个接口输入的是rs2的数据还是imm。
* 控制信号ALUSrc用来控制选择。
* 右侧MUX用来选择写回寄存器堆的数据来源（ALU或内存），由MemtoReg控制。

**对于sd** : 它是将rs2的值写入Mem，那么Read data2就要连接到data memory的write data输入。（图中也有这条）还需要一个MemWrite来使能。

#### 1.5.3 改变控制流：分支指令

eg：beq x1,x2,offset

* 比较寄存器x1和x2的值。
* 如果相等，PC要跳转到 当前PC + (符号扩展后的offset << 1)。
* 如果不相等，PC正常更新为PC + 4。

**notice:**
* jal指令中，跳转目标为PC+imm。因为PC总是2字节（16位指令）或4字节（32位指令）对齐的，最低位总是0，所以在存imm时直接省掉最低位。所以这两种的真正跳转目标为：
    > PC = PC + ( imm_encoded << 1 )
    //20位立即数先做符号扩展，并左移一位，产生32bit的有符号数

* 对于branch指令，计算上与jal是一样的：
    > PC = PC + ( imm_encoded << 1 )
    //目标地址由imm_encoded符号扩展，并左移1位再与PC值相加产生；

* 而对于jalr指令，由于是从rs1中读出来的，并不一定是偶数，因此不用对imm做处理。而在相加完之后再清零。
    > jalr rd, offset(rs1)
    PC = ( Rs1 + imm ) &~ 1 
    //&~1是用掩码0xFFFFFFFE来将最低位清0.
 
![4-9](../image/2025-11-06-20-34-59.png)

* 为ALU添加一个Zero信号输出，用于体现比较结果
* PCSrc选择下一个PC地址是+4还是跳转到指令中的地址
* Zero应该和beq判断信号（即，若这条指令是beq时为高电平）一起作为PCSrc的决定因素。故Zero不应该接到Mem

### 1.6 控制信号的生成

* 本质：一个纯组合逻辑电路。
* 输入：指令的opcode字段（bits[6:0]）。为什么是opcode？因为opcode是定义指令类型的最主要字段。
* 输出：我们之前设计中用到的所有控制信号：RegWrite, ALUSrc, MemRead, MemWrite, MemtoReg, Branch，以及一个中间信号ALUOp。

#### 1.6.1 两级控制

##### （1）主控制unit

只负责“宏观决策”。

它仅根据opcode来识别指令的大类，**并生成除ALU具体操作外的所有控制信号**。对于ALU，它只生成一个2位的ALUOp信号，告诉下游“这是一次R-Type运算”或“这是一次用于地址计算的加法”等。

**如图：**

![4-15](../image/2025-11-07-10-12-34.png)

##### （2）ALU控制单元

接收主控传来的ALUOp和指令中的funct字段（Fun3和Fun7），然后翻译成ALU真正需要的4位控制码。

![4-16](../image/2025-11-07-10-13-33.png)

**主控制单元真值表**

![4-17](../image/2025-11-07-10-16-07.png)

* 即根据OPcode会输出什么内容。是规定好的

**ALU控制单元真值表**

![4-18](../image/2025-11-07-10-17-33.png)

当主控制器看到opcode是R-Type时，它输出ALUOp=10。ALU控制器看到ALUOp=10，就知道要去检查funct字段。如果funct7+funct3组合表示add，它就输出0010给ALU；如果表示sub，它就输出0110，以此类推。

**综上，我们可以得到一个单周期处理器的架构：**

![4-19](../image/2025-11-07-10-18-30.png)

它很优雅，因为它简单。 每条指令在一个时钟周期内完成，CPI=1，逻辑清晰。

但它性能极差，因为它是一个“木桶”。木桶的容量由最短的木板决定，而**我们单周期处理器的时钟周期，则由最长的那条指令的执行时间决定** 。通常是ld指令，因为它涉及的路径最长：

    取指 -> 读寄存器 -> ALU计算地址 -> 读内存 -> MUX选择 -> 准备写回寄存器。

这意味着，一条执行路径很短的add指令，也必须浪费大量时间，去等待一个为ld指令量身定做的、漫长的时钟周期。所有指令都被迫与最慢的指令耗时相同，这造成了巨大的资源浪费。

从而我们需要引入流水线设计。
