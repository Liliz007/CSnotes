# 层次存储

# 1. Intro

自从计算机诞生以来，CPU的运行速度与主存（DRAM）的读取速度之间的差距，不仅没有缩小，反而在以惊人的速度持续扩大。我们称之为**内存墙（Memory Wall）**。这是我们提高计算机性能的一个严峻挑战。

今天，我们的任务就是正面迎击这个挑战。我们将探索计算机体系结构中另一个与流水线同等重要的基石——**存储器层次结构（Memory Hierarchy）**。我们将学习如何利用巧妙的结构设计和深刻的程序行为洞察，为CPU构建一个既大又快的存储系统幻象。

# 2. Memory Technologies

# 3. 局部性原理

绝大多数程序运行时都表现出强烈的局部性，即一次仅能访问存储空间中的一小部分

## 3.1 时间局部性(Temporal locality)

如果一个数据项在某个时间点被访问了，那么在不久的将来，它有极大的概率会被再次访问。

例如：

1. 循环体内的指令会反复执行；循环变量被反复访问
2. 栈顶附近的变量会被频繁访问

## 3.2 空间局部性(Spatial locality)

如果一个数据项被访问了，那么与它地址相邻的其他数据项，也很有可能在不久的将来被访问。

例如：

1. 顺序执行的指令流：这是最强的空间局部性体现。
2. 数组遍历：访问array[i]之后，通常会接着访问array[i+1]。
3. 数据结构：结构体或类的成员变量在内存中通常是连续存放的。

# 4. 层次存储的构建

![](../image/2025-11-25-10-40-27.png)

较近的（如上周的）数据放到DRAM memory(主存)中，再从DRAM中选取更近访问的放到SRAM memory(Cache)中。总之disk->DRAM->SRAM是一个包含的关系。

**一个典型的存储器层次结构：**

![](../image/2025-11-27-22-08-03.png)

* L0: CPU寄存器 (SRAM)
* L1 Cache (一级缓存): 通常在CPU核心内部，使用最快的SRAM。容量极小（几十KB）。
* L2 Cache (二级缓存): 通常也在CPU芯片上，使用速度稍慢但容量更大的SRAM。容量几百KB到几MB。
* L3 Cache (三级缓存): 在现代多核CPU中常见，被所有核心共享，容量更大（几MB到几十MB）。
* 主存 (Main Memory): (DRAM) 容量巨大（几GB到几百GB）。
* 本地二级存储: (闪存SSD / 磁盘HDD) 非易失性，容量TB级别。
* 远程二级存储: (分布式文件系统 / 云存储)

**上述结构的大致工作流程：**

* 当CPU需要一个数据时，它首先访问最顶层的L1 Cache。
* 如果数据在L1中（命中，Hit），CPU直接获取，速度极快。
* 如果数据不在L1中（缺失，Miss），则访问下一层L2 Cache。
* 如果在L2中命中，则将包含该数据的整个块从L2复制到L1，然后再提供给CPU。
* 如果L2也缺失，则继续访问L3，乃至主存。
* 这个过程一直向下，直到找到数据为止。然后，数据块会沿着层次结构，被一级一级地复制上来，最终到达L1 Cache和CPU

术语和详细过程会在下面的内容讲解。

**对局部性的利用：**
1. 时间局部性：一个块被提升到高层缓存后，由于后续很可能再次访问它，此时就会都是高速的Hit
2. 空间局部性：由于是把访问的Byte所在的一整个Block都提升了，所以接下来访问其相邻的Byte也都是高速的Hit

## 4.1 重要术语

1. **block/line**：数据在相邻层次间复制、移动的最小单位。块越大，越能利用空间局部性；但太大会浪费传输带宽，过犹不及
2. **Hit(命中)**：想访问的数据刚好在上层中.
   * 命中率(Hit rate)：命中次数 / 总访问次数。这是衡量缓存效率的最重要指标。
   * 命中时间：访问当前层次并确定是命中的时间。包括地址比较、数据读取等。对于L1 Cache，通常是1-4个时钟周期。
3. **Miss(未命中or缺失)**:上层中没有这个被访问的block，需要去更大更慢的层次寻找
   * 缺失率(Miss rate): 1-Hit rate
   * 缺失代价(Miss Penalty):将数据copy到upper level，亡羊补牢一下；并且**再从上层读取**

性能衡量的最终指标：平均访存时间(AMAT,average memory accessing time)，即访一次存并获得数据的平均时间——
$$
AMAT = Hit Time + Miss Rate \times Miss Penalty
$$ 
  >直接用Hit Time而不用乘hit rate是因为，进行miss penalty之后还要从上层再hit一次。所以最终结果都是hit，只是中间需不需要加上额外的miss penalty罢了。

我们的所有优化手段，最终都是为了降低AMAT。途径有三：

1. 降低Hit Time（如使用更简单的Cache设计）
2. 降低Miss Rate（如使用更大的Cache、更聪明的放置策略）
3. 降低Miss Penalty（如使用多级缓存、高速总线）

## 4.2 Cache: Deal with speed

用来解决主存速度配不上CPU速度这一矛盾。

缓存的设计，必须回答四个核心问题，这四个问题定义了所有缓存的形态：

1. **块放置** ：一个从主存取来的块，可以放在缓存的哪个位置？——**映射机制**
2. **块识别** ：当CPU给出一个地址时，如何快速判断它所对应的块是否在缓存中，以及在哪个位置？——**Tag bits**
3. **块替换** ：当发生缺失，且缓存中没有空闲位置时，应该把哪个旧的块替换出去？——LRU or MRU,etc
4. **写策略** ：当CPU执行写操作时，数据应该如何更新到缓存和主存中，以保证数据的一致性？——**when hit:写穿/写回；when miss:写分配/写不分配**

由于下层比上层大，因此在上层缓存为下层的块分配位置时，会出现多个块对应同一位置的情况。那么我们就要考虑如何设定这个位置分配策略。

#### A. 直接映射

这是最简单、最基础的缓存放置策略.

**放置策略：** 一个主存块，只能被放置到缓存中的一个**唯一确定**的位置。

**映射规则：** $ Cache Block Index = (Mem数据块号) mod (Cache的行数)$. 即用主存的块号数对Cache的总块数取余。

**硬件实现的巧妙简化：** 如果缓存的块数是$2^n$，那么取模运算就可以简化为取主存块地址的低n位（只是取余的一个快速结论）。这使得地址到索引的映射在硬件上实现起来极其简单和快速，只需要进行地址位的截取，无需任何计算。

![](../image/2025-11-27-22-47-17.png)

#### B. 全相联(Fully associative)

* 块随便放Cache的哪一行。

![](../image/2025-12-02-10-44-03.png)

#### C. 组相联(Set associative)

将Cache分为大小为n个块的组。

* 组索引 = 数据块地址 MOD 缓存中的组数量
* 如果每组包含n个数据块，则该Cache被称为n路组相联（n-way set associative）。
* 直接映射等价于1路组相联；而全相联缓存则是m路组相联（针对具有m个块的缓存）。

### 4.2.2 块识别：标签tag与有效位Valid Bit

光用Cache Block Index是无法准确定位一个given data的，因为多个不同的主存Block都可能映射到同一个Cache块，因此我们需要识别现在存的是哪个数据块。
Cache的一行包含四部分：Tag,Valid,Dirty,Data

![](../image/2025-11-25-11-17-05.png)

**1. Tag位**

存储了该数据块**原始的主存块地址**的高位部分。（除去Index和Byte Offset剩下的部分）
当CPU访问一个Addr时：
* 使用地址的索引位，定位到缓存中的某一行(块)
* 将地址的Tag和该行存储的Tag进行比较
* 如果相等，就说这个Tag位是正确的/有效的

**2. Valid Bit**

缓存刚加电时，里面是无效的垃圾数据，或者某个位置可能从未被使用过。因此我们要用一个Valid Bit来标志此空间是否是有效的数据。
* 当一个有效的数据块被加载进来时，将该位设为1；初始状态或被删除后，置为0。

**3. Dirty Bit**

用来判断该块的数据是否为最新。Dirty=1，表示该数据还没有写回Mem，先写回去，再对此块进行更新。

**4. Data**

真正存储的数据。从主存中提升上来的那些。

**最终的命中条件：** index,Tag,Valid,Dirty都有效，则真正命中了。


**计算题：** 

![](../image/2025-11-25-11-34-54.png)

一行是$2^m \times 32+(64-n-m-2)+1$，整个Cache共有$2^n$行。

   * miss penalty变大

### 4.2.4 Cache读写的Hit/Miss

分为两类，数据Cache和指令Cache。read hit没啥好说的。

**（1）Cache Read Misses**

1. data cache miss
2. instruction cache miss:
   * 将原始的PC值发送到内存(current PC-4)（已经取指到下一条了，在此时miss，则退回上一条要-4）
   * 对这个miss指令的地址，命令主存执行read操作，并等待其完成读取操作
   * 将来自内存的数据的值写入Cache对应Block的data部分，地址的高位放入Block的Tag字段，并拉高有效位。
   * 从第一步重新开始执行，这次会在Cache中直接Hit。

**（2）Cache Write Hits**

![](../image/2025-11-28-09-55-25.png)

有两种形式，写穿和写回，如上图。

1. **写穿**：写到Cache和Mem中，确保了Cache和Mem中的数据一致，但是很慢，浪费了Cache的高效性
   * 解决策略：在Cache和Mem之间增设一个write buffer。
2. **写回**：只写到Cache中，写完就给出写相应。这样会Cause Inconsistent.
   * 解决策略：之后再将data从Cache里写回Mem里。（当后续需要替换这个块时，如果它是dirty的，就写回Mem。然后新数据就只用写到Cache中）

**直写式优势：**
- 只需要一个valid bit，不用dirty bit
- 读缺失不会引发写操作：因为每次都写到底，直接把需要的块替换进来，不用像写回一样总把脏块写回Mem。
- 存储的不同层次的数据一致
- 实现简单

**写回式优势：**
- 需要dirty bit
- 对于写操作，带宽占用大幅降低：只有当替换/disable一个块时，才需要更新到Mem中，其他时候不用对Mem进行访问。

**（3）Cache Write Misses**

写的块不在Cache中时，我们针对目标块，对Cache有两种处理方式：

1. **写分配**(write allocate)：在未命中时为Cache分配一个line，将整个数据块从内存取入缓存。（一般write back用这个，因为终点就是Cache了肯定要给Cache分配啊）
2. **绕写**(write around)：AKA写不分配，不在Cache中分配Block也不将数据取上来，而是直接写入Mem

见如下例题：

* 对于写到L1：

**（4）Cache Wirte Stall**

对于Write through，存在一个write stall
1. 写入停顿(write stall)——当CPU在直写操作期间必须等待写入完成时,产生写入停顿。
2. 解决方式：写缓冲区(write buffer)
   * 一个能暂存少量待写入主内存数据的小型缓存。
   * 为避免写入停顿，多数CPU采用写缓冲区。
   * 当写入操作集中时，该缓冲区能有效缓解问题。
   * 但若突发写入量超过缓冲区容量，仍无法完全消除停顿，因为缓冲区可能被填满。此时又会产生write stall了

* 从Mem回到CPU是不用buffer的，因为从下往上拿是快的。

### 4.2.5 块替换

在直接映射缓存中，只有一个可被替换的块。在组相联和全相联缓存中，存在N个块（其中N为相联度）可被替换。

**替换策略：**
1. **随机替换** —— 随机选取任意块
   * 硬件实现简单，仅需随机数生成器
   * 将分配均匀分散在缓存中
   * 缺点：可能驱逐即将被访问的块
2. **最近最少使用**(LRU,Least Recently Used) —— 选取组中最近最少被访问的块
   * 根据时间局部性：假定最近被访问的块更可能再次被引用
   * cost: 这需要在缓存中添加额外位来追踪访问记录
3. **先进先出(FIFO)** —— 从缓存中选择最早进入的块来替换
   * 最简单粗暴

### 4.3.1 术语

![](../image/2025-12-04-14-49-56.png)

**注意页错误**：是指page不在Mem中。
**地址**：CPU给出的是虚拟地址，对应Mem中的地址叫物理地址。
**虚拟页号**：Virtual Page Number,VPN
**物理页号**：Physical Page Number,PPN

多个程序可以共享虚拟地址，映射到的物理地址却不同。

* 虚拟page数量多于物理page
* page faults：**Page不在主存Mem中**，要去辅存disk找。我们要尽量减少page faults——
  * 由于辅存disk很慢，所以要尽量把page设计大一点。
  * 使用LRU和全相联，降低miss rate
  * 用软件解决
  * 用write back而非write through（即，不写回disk，不然太慢了）

### 4.3.2 page table read（必考）

![](../image/2025-12-09-10-20-14.png)

1. 目标：将虚拟地址->物理地址。其中Virtual Addr = {VPN,page offset}
2. 将virtual addr翻译到phys addr时，page offset不变
3. 在VM机制中，**page table的一行称为一个entry**。
   1. valid位=1，则page在memory中，其physical page number（上图中标注有误）就会存在entry中。
   2. valid=0，表示此page位于disk中，后面那个长条存的是disk addr
4. 页表寄存器：每个进程有各自的页表（他们位于Mem中），而页表寄存器存着每个页表在Mem中的地址。
5. 页表(page table)、程序计数器(PC)和页表寄存器(page table register)共同指定了程序的运行状态。每个进程都拥有独立的页表。
6. page offset是在一个page中索引一个byte的index. （其实还是byte offset）。
   * 因此一个4KB的page，共$2^{12}$B，所以page offset有12bits

![](../image/2025-12-09-10-26-17.png)

* page table reg->Mem：全相联。即page table可以存在Mem中的任意位置。
* VPN->page table entry：直接映射。

**【计算例题】**

![](../image/2025-12-09-10-45-35.png)

virtual addr = {VPN,page offset}，其中page offset = 12bits -->VPN = 24bits

PPN = 32-12 = 20 bits

1 entry = 20 + 1 + 1 = 22bits

总页数：共2^VPN页。故page table共有2^24个entry.

从而page table总大小：22*2^{24}

### 4.3.3 deal with page faults

**当操作系统创建一个进程时，通常会在disk上为该进程的所有页面分配空间。**

1. 发生fault时，操作系统(OS)将通过异常机制获得控制权
2. OS先根据page table去disk中寻找所需page
3. 接下来，操作系统会将请求的页面调入主存。如果主存中的所有页面都已被占用(即Mem已填满)，操作系统将采用LRU（最近最少使用）策略选择一个页面进行替换。

### 4.3.4 page wirte

* 由于磁盘访问速度过慢，虚拟内存系统无法采用write through策略。
* 取而代之的是，它们必须使用write back策略。为此，计算机需要在页表项(page table entry)中**增加一个脏位**。
* 当页面首次被写入时，脏位会被置位（拉高）。若某页面的脏位=1，则该页面在被替换前必须写回磁盘（因为此page是新写进来的，还没有同步到disk）

### 4.3.5 加快地址翻译:TLB

访问一个page时，我们都至少需要两次访问Memory：（1）访问page table（是的page table也在Mem中），（2）访问Mem。这样会有点慢。我们要想办法利用一下局部性原理

* TLB: (Translation-lookaside Buffer)快表。相当于page table的Cache。比成Cache意味着，TLB也存的是一个个entry，用来映射到Mem中的页（因为要快，所以TLB不含disk页的entry）
  
![](../image/2025-12-09-11-04-17.png)

* **Ref**：Reference位，也常称为访问位（Accessed Bit）或使用位（Use Bit），用来跟踪一个页面是否被访问过（对应页面替换时的LRU策略）
* VPN作TLB的index，同时也作为Tag与TLB的对应行的Tag比较。
* 若在TLB没找到，再到page table中找。
* 在page table中发生page fault(valid=0)，再到disk中找
* TLB可以用直接映射、组相联、全相联：指的是一个VPN对应的entry在TLB中的存放方式。

### Summary

总之VM和Cache的想法是一样的，用DRAM来缓解Disk超慢的drawback。另外VM还有其他的优势：

1. **程序隔离与保护** ：每个进程都有自己独立的、私有的虚拟地址空间。操作系统通过控制页表，确保一个进程无法访问另一个进程的内存，提供了坚实的内存保护。
2. **内存管理简化** ：程序员和编译器可以假设自己拥有一大片连续的内存空间，而无需关心物理内存的碎片化问题。内存的分配和布局由操作系统全权负责。
3. **高效的进程间共享** ：操作系统可以让**不同进程的虚拟页，映射到同一个物理页上**（的不同Byte），从而实现代码库或共享内存的高效共享。
