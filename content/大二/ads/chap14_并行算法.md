# 1. Intro

并行算法指的是：在算法设计层面，主动将一个大问题分解成多个可以同时执行的子任务，并设计它们之间的协作方式

# 2. 并行计算模型

本节介绍PRAM和WD.

## 2.1 PRAM:并行随机存取器

并行随机存取机 (Parallel Random Access Machine, PRAM) 是并行算法理论中最经典、最重要的模型。它描绘了一个理想化的并行计算环境。

可以将读写、计算都抽象为"1"个操作来描述。

![](../image/2025-12-16-14-01-34.png)

**【PRAM构成】**
1. 多个同步处理器: 拥有P1,P2,...,Pn等多个处理器。它们共享同一个全局时钟，在每个时钟周期同步执行指令。
2. 一个共享内存: 所有处理器都可以访问一个无限大的共享内存空间。
3. 单位时间访问: 任何处理器对共享内存的任何位置进行一次读、写或进行一次本地计算，都只花费一个单位时间。   

在PRAM模型中，我们经常使用一个特殊的关键字 **pardo (parallel do)** 来表示一个并行循环。例如：

    for Pᵢ, 1 ≤ i ≤ n pardo 
        A(i) := B(i)

这行代码表示在同一时间内并行执行A(1)=B(1) ... A(n)=B(n)这n个赋值，用时为1 Unit Time.如下图

![](../image/2025-12-16-14-13-02.png)

## 2.2 内存访问冲突及resolution

如果多个处理器在同一时间步试图访问同一个内存单元，会发生什么？这就是访问冲突。

根据 **【如何处理读写访问冲突】**，PRAM模型可以分为几类：

>注意，这几类的时钟都遵循"读->处理->写"的划分，不存在写了之后在这个时钟内被读到新值的情况。

1. **EREW** (Exclusive-Read Exclusive-Write)：独占读and独占写
   1. 一个时间步内，一个Mem Unit只能被一个处理器使用
   2. 最容易实现，但限制最大，最不灵活
2. **CREW** (Concurrent-Read Exclusive-Write)：并发读，独占写
   1. 允许多个处理器同时读同一个Mem Unit
   2. 仍然只允许一个处理器写
   3. 常用且实用
3. **CRCW** ：并发读，并发写
   1. 最牛逼。允许多个处理器同时读，也允许同时写。
   2. 并发写的问题：如何决定最终值？
      1. 任意规则(Arbitrary): 任意一个成功写入。我们不知道是哪个
      2. 优先级规则(Priority): 处理器序号最小或最大的那个成功写.允许设置优先级为-1，从而立刻抢占访问权。eg：无人驾驶程序
      3. 公共规则(Common): 只有所有处理器写入相同的值时才写成功。否则行为未定义。适用于容错率低的场景。
      4. 求和规则(Sum): 所有写入的值相加，作为最后写入的值

强度：CRCW > CREW > EREW。强模型上能兼容弱模型的算法，反之不一定

# 3. WD(Work-Depth)模型

更抽象。我们只关心工作量和深度：
* 工作量(Work)：W(N)，算法执行的总操作数
* 深度(Depth)：T(N)，算法最长依赖路径的深度

**好处：** 将算法与机器解耦（一个算法的W(N)和T(N)是固定的），不用管有多少处理器P，迁移性好。

![](../image/2025-12-16-14-31-53.png)

## 3.1 复杂度分析——布伦特定理,Brent

从串行->并行，性能提升的上界？

显然很多问题不可避免地有串行的要求，不可能规模为N的问题，在N个处理器执行时直接优化成O(1)了。Brent定理解释了WD模型和PRAM模型之间的关系：
**一个具有W(N)工作量，T(N)深度的算法，可以在一有p个处理器的PRAM上，于$O(W(N)/p+T(N))$内完成**。
* $W(N)/p$：是将全部工作平均分给p个处理器所需要的理想时间
* $T(N)$：可以理解为关键路径的长度、不得不串行的时间。有再多的处理器也无法优化。
* 实际运行时间取决于这两者

![](../image/2025-12-16-14-44-55.png)

* 对此求和算法，W(N)=O(N)，T(N)=O(logN)。则总运行时间为$O(N/p+logN)$
* 由于非并行的运行时间数值上就是工作量W，故即使只有很少的处理器，运行时间依然可以被并行优化。
* 当$p=N/logN$时，时间为$O(logN)$，获得了最优加速效果（时间好的同时p尽量少）。

我们希望能效比也是好的，也就是说W(N)也不能太大。总之，设计算法时尽量使T(N)和W(N)都小。（既要马跑得快又要马不吃草）

### 随机采样法(Random Sampling)

![](../image/2025-12-23-15-14-07.png)

从规模为N的数据中随机抽出$N^{7/8}$的样本。（相当于每$N^{1/8}$抽一个。对于计算机等应用场景来说这是一个稀疏的抽样）

样本得到的最大值只有1/16的概率是全局最大值

把样本划分为每块大小为$n^{1/8}$的块。共有$n^{3/4}$块，对这些块并行找最大值，得到$M_i(1)$. 这一步的时间复杂度为$T=O(1),W_i=O((n^{1/8})^2)=O(n^{1/4})$.

再把这$n^{3/4}$个最大值作为一个整体，划分为大小为$n^{1/4}$的$n^{1/2}$个小块。对这些小块再用并行找最大值算法。

失败率是$O(N^{-c})$
