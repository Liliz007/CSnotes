# 1. Introduction

## 1.1 边的旅程 vs. 点的旅程

### 1.1.1 Euler Circuit,欧拉回路(easy)

* 任务：给定一张图，你能否找到一条路径，从某个点出发，不重不漏地走过**每一条边**恰好一次，最后回到起点？
* 答案：这是一个经典的可高效解决的问题。一个连通图存在欧拉回路的充要条件是：图中所有顶点的度数（连接该点的边的数量）都是偶数。判断这个条件并找出路径，我们只需要遍历一遍图，时间复杂度为$O(|V|+|E|)$，其中$|V|，|E|$分别是顶点数和边数
  
### 1.1.2 Hamilton Cycle,哈密尔顿环路(hard)


* 任务：同样给定一张图，你能否找到一条路径，从某个点出发，不重不漏地走过**每一个顶点**恰好一次，最后回到起点？
* 答案： 这个问题只是把“边”换成了“点”，难度却呈指数级暴增。人类尚未发现任何一个多项式时间的算法来解决它。最直观的暴力搜索方法是尝试所有顶点的排列，其数量级是阶乘级别的$O(N!)$

## 1.2 最短路 vs. 最长路

### 1.2.1 单源无权最短路(easy)

* 任务：在一张所有边长度都为1的图中，找到从一个指定的源点到其他所有点的最短路径。
* 答案：广度优先搜索BFS可解决，复杂度为$O(|V|+|E|)$

>BFS就是一层层向外扩散。从s出发，先遍历完s相邻的所有结点，再遍历这些结点相邻的结点...见下面伪代码

```c
//初始化所有距离
for v in V:
  visited[v] = false
  dist[v] = INF

Queue q
visited[s] = true //源结点
dist[s] = 0
q.push(s) //入队。因为后面新来的可能离s更远，故要FIFO。只能用队列

while q 非空:
    u = q.pop()  //出队
    for each v ∈ Adj[u]:  //处理与u相邻的结点
        if !visited[v]:
            visited[v] = true
            dist[v] = dist[u] + 1
            parent[v] = u //标记来源
            q.push(v) //入队

```

### 1.2.2 单源无权最长路(hard)

* 任务：在同样的图中，找从某个源点到某个终点的最长simple path.（简单路径要求顶点不能重复）
* 答案：与Hamilton同样难，目前没有已知的多项式时间算法。

### Observations

这些例子揭示了计算世界中的一个深刻分界线。一类问题，我们称之为“易解的”，拥有多项式时间 (Polynomial Time) 算法。另一类问题，我们称之为“难解的”，目前只存在指数时间 (Exponential Time) 算法。在计算机科学中，我们通常将“多项式时间”视为“高效”“实际可计算”的标准。

**注：** 多项式时间$T(N)=O(N^k)$ ，k是常数；指数时间$O(2^N),O(N!)$等

>阶乘甚至比指数增长还快，坏得没边了。

# 2. 计算的极限

在“难解”之上，还存在一个更终极的边界：**不可判定问题 (Undecidable Problems)**。对于这些问题，我们甚至无法保证能设计出一个算法，在有限时间内对所有输入都给出正确的“是”或“否”的回答。

## CASE:停机问题

* 问题陈述：是否可能编写一个程序，它能分析任何一段C代码，并准确判断这段代码在给定的输入下是**会最终停止，还是会陷入无限循环？**

* 答案：不可能。

证明如下。（反证法）

### step1.假设存在这种算法

假设存在这样一个万能程序。我们把它命名为 Halts(program, input)。它接受一个程序 program 和它的输入 input。如果 program 在 input 上运行会停机，Halts 就返回 true；如果会无限循环，就返回 false。

### step2.构造悖论程序

现在，我们利用这个假设存在的 Halts 函数来构造一个“刁难”它自己的新程序，我们称之为 Paradox(P)。这个程序只接受一个输入，就是另一个程序的代码 P。

```c
//pseudo code
function Paradox(program P)
{
    // 调用我们假设存在的 Halts 函数，检查 P 在以自己的代码为输入时是否会停机
    if (Halts(P, P) == true) 
    {
        // 如果 Halts 说 P(P) 会停机，那么 Paradox 就故意进入无限循环
        while (true) 
        {
            // loop forever
        }
    } 
    else 
    {
        // 如果 Halts 说 P(P) 会无限循环，那么 Paradox 就立刻停机
        return;
    }
}
```

**那么，Paradox(Paradox)** 会发生什么，会停止还是无限循环？

我们分别分析两种情况，看看能不能找到矛盾。

**假设Paradox(Paradox)会停机。**
那么Paradox中走的就是else线，也就是说Halts判断Paradox(Paradox)会无限循环，这跟会停机的假设相矛盾。

**假设Paradox(Paradox)会无限循环。**
那么Paradox中走的就是if线，就是说Halts判断会停，跟假设矛盾了。

如图：

**从而我们得出结论：Halts程序不存在(除了这一点，其他地方的推导都是严密的，故只能是这里有悖论)，停机问题是不可判定的。**

从而，NP完备就处在“高效可解”和“完全不可解”之间。

# 3. P/NP/NPC

## 3.1 计算模型：图灵机

阿兰·图灵提出的图灵机 (Turing Machine) 是一个强大的理论模型，它由一条无限长的纸带、一个读写头和一套有限状态的控制器组成。（如下图）它虽然简单，但被证明能模拟所有现代计算机能完成的计算。

![](../image/2025-11-18-14-17-26.png)

**关键在于区分两种工作模式：**

1. **确定性图灵机** (Deterministic, DTM): 在任何时刻，根据当前状态和读写头下的符号，下一步的操作是唯一确定的。这就像我们日常编写的程序，一步接一步，路径是唯一的。
2. **非确定性图灵机** (Nondeterministic, NTM): 这是一种理论上的“神谕”机器。在某些时刻，它面临多个选择时，总是能直接猜到能解出答案的选项。可以这样理解：
    * **幸运猜测视角**： 如果存在一条能够导致问题解决（接受状态）的计算路径，**NTM总能幸运地猜中并沿着这条路走下去。**
    * **并行宇宙视角**： 当面临选择时，NTM会分裂成多个“宇宙”，同时探索所有可能的路径。只要其中任何一个宇宙找到了解，整个计算就成功了。

NTM是一个强大的数学工具，它引出了我们今天的主角——NP类问题。

## 3.2 复杂性类：P/NP

**P类：** Polynomial time，多项式时间，所有可以由一个**确定性**图灵机在多项式时间内解决的**判定问题**的集合。 通俗解释： 这类问题，我们能找到一个高效的算法，在合理的时间内直接计算出答案（“是”或“否”）。
>例如：排序、最短路径、判断图是否连通等。

**NP类：** Nondeterministic Polynomial Time，**非确定性多项式时间。**
* def1:**（基于验证）** 所有可以在多项式时间内被一个确定性图灵机**验证**【它结果为“是”的答案】的判定问题的集合(A problem is NP if we can prove *any solution is true in polynomial time.*)
* def2：**（基于非确定性计算）** 所有可以由一个非确定性图灵机在多项式时间内**解决**的**判定问题**的集合。

**def1的“验证”的含义：**
想象一下，哈密尔顿环路问题。要找出一个环路非常困难。但是，如果我声称找到了一个，并把这个环路的顶点序列（我们称之为 **“证书 (certificate)”**）给你，你来验证它是否正确，就非常简单了：
1. 检查这个序列是否包含了所有顶点，且每个顶点只出现一次。
2. 检查序列中相邻的两个顶点在原图中是否有边相连。
3. 检查首尾顶点是否相连。

从而，Hamilton Cycle问题是一个NP问题。

![](../image/2025-11-18-14-27-06.png)

上面这个问题是可计算的s，但它不是NP，复杂度为$O(N!)$（直接暴力枚举所有排列即可）。

**NP-hard：** 如果所有NP都能在多项式时间内归约到一个问题Q，那么Q就是一个NP-hard问题。我们**并不要求Q本身是NP问题。**

### 这两类的关系

显然$P \subseteq NP $。也就是说，可以由DTM在多项式时间解决的问题，必然可以由NTM在多形式时间内解决。

但是目前无法证明$P=NP\ or\ not.$

为了更严谨，理论计算机科学家使用“语言”来描述问题。

### 3.3.1 定义

![](../image/2025-11-18-15-14-05.png)

**抽象问题：** 是一个从问题实例I到问题答案S的映射二元组。
* Alphabet $\Sigma$ : 一个有限的符号集合，如0，1
* String : 由字母表中的符号组成的有限序列
* Language L : 某个字母表$\Sigma$上所有可能字符串的集合的一个子集
* 所有由$\Sigma$上的字符组成的有限字符串记为$\Sigma$*

**eg：** L={所有二进制表示的质数}

**一个判定问题可以看作是判断一个给定的输入字符串是否属于某个特定语言。**

![](../image/2025-11-19-20-53-49.png)

#### 对于P

$$
L=\{x∈\Sigma^*|A(x)被接受\} \\
其中A是多项式时间的确定性算法
$$


#### 对于NP

对于语言L，如果$x∈L$，那么存在一个证书$y$，和一个确定性多项式时间的算法A（用来验证x,y是否满足某种关系），有$A(x,y)=1$.

如果$x \notin L$，那么就没有这样的证书y满足$A(x,y)=1.$

从而语言L可以如下定义：
$$
L=\{x∈\Sigma^*|\exist y,A(x,y)=1\} \\
其中A是一个多项式时间的确定性验证算法
$$

## 3.4 NP-Completeness.NP完备性

在NP这个大家族里，有些问题格外“尊贵”，它们是NP问题中最难的一批。所有的NP问题都可以**规约到**NPC问题（被覆盖）。这就是 **NP完备 (NP-Complete, NPC) 问题。**

NPC问题是NP和Decidable的边界。只要为任意一个NPC找到了多项式解法，那么就能为所有NPC找到多项式解法。

### 3.4.1 第一个被证明的NPC——SAT问题

**SAT问题(Satisfibiality)，布尔可满足性问题：**

* 输入：一个布尔逻辑公式，由多个变量（x₁, x₂, …）、逻辑与(∧)、逻辑或(∨)、逻辑非(¬) 和括号组成。

* 问：是否存在对这些变量的 True/False 赋值，使得整个公式为 True？

### 3.4.2 多项式时间规约(Polynomial-time Reduction)

归约是比较问题难度的核心工具。我们说“问题A可以归约到问题B”，直观上意味着 **“问题A不比问题B更难”。**

**定义：** 如果存在一个能在多项式时间内完成的转换函数（操作）$f$，它能将问题$L_1$的任何实例$x$转换成问题$L_2$中的一个实例$f(x)$，并且满足以下转换条件：

$$
x ∈ L_1 \iff f(x) ∈ L_2
$$

**即x是L1的“是”实例，当且仅当f(x)是L2的“是”实例。**

那么此时我们说L1多项式时间归约到L2，记作$L_1 \le_p L_2$ （$\le_p$ 相当于no harder than.）

这个转换函数f就像一个“翻译器”。如果你有一个能解决L2的“神谕”或黑盒子，那么通过这个翻译器，你就可以在多项式时间内解决L1了。流程如下：

![](../image/2025-11-18-14-41-07.png)

#### 证明NPC

证明一个新问题B是NPC的通用步骤：
1. 证明B是NP的：说明可以在多项式时间内验证给定的解
2. 找一个已知的NPC问题A
3. 证明$A \le_p B$：将A规约到B

### 3.4.3 实例

#### CASES 1. HCP->TSP

**问题描述：**
1. HCP(Hamilton Circle):对于一个图G，是否有一条简单环路刚好不重不漏地经过所有Vertices？
2. TSP(Traveling Salesman):对于一个带权完全图G'（节点两两之间都有边），是否有一条简单环路刚好经过所有顶点，且边的总权重≤K？（K是一个给定的整数）

已知HCP是NPC，下面证明TSP也是NPC。我们希望把HCP规约到TSP，即证明HCP不比TSP更难。

**Proof：**

![](../image/2025-11-19-20-24-27.png)

1. 显然，我们可以在多项式时间内验证TSP的一个given solution（遍历一次即可）。因此TSP是NP
2. 下面我们证明$HCP \le_p TSP$.也就是将HCP规约到TSP，也就是找到一个转换函数f，在TSP中构造出HCP的一个同构问题。从而也就有**G中有Hamilton环路 $\iff $ G'中存在总权重 ≤K 的TSP**。

![](../image/2025-11-19-20-28-18.png)

证明规约的正确性：

![](../image/2025-11-19-20-32-53.png)

**规约复杂度：从HCP构造TSP**
HCP的顶点数为N，边数最多为$O(N^2)$
为TSP构造完全图，边数为$C_N^2=O(N^2)$
为完全图的边赋值：遍历一次，复杂度为$O(N^2)$

故总复杂度为：$O(N^2)$，是多项式时间规约。

#### CASES 2. 子团(Clique)与顶点覆盖(Vertex Cover,VC)

**问题描述：**
1. 子团问题(Clique)：给定图G=(V,E)和整数K，问G中是否存在一个大小为K的团？
   * 团是一个**顶点子集**，任意两点之间有边相连。注意不是完全图，因为团 **只包含顶点** 而不含边）
2. 顶点覆盖问题(Vertex Cover,VC):给定图G=(V,E)和整数K，问G中是否存在一个大小为K的顶点覆盖？（VC是一个顶点子集V'，使得 **图中每条边都至少有一个端点在V'中** ）

假设我们已知Clique是NPC，我们把Clique规约到VC。

**Proof：**
1. 显然VC是NP，检查顶点数是否为K和每条边的端点，这个检查的复杂度显然是多项式的。

```c
//pseudo code
function VerifyVertexCover(Graph G, int K, Set V_prime):
  if V_prime.size() != K:
    return false
  
  for each edge (u, v) in G.edges:
    if u is not in V_prime and v is not in V_prime:
      return false // 这条边没有被覆盖
      
  return true // 所有边都被覆盖
```

2. 证明Clique$\le_p$VC.
