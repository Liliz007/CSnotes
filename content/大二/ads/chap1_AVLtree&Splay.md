#  AVLtree & SplayTree

## 1. AVL tree

- Problem : 对于BST，Although Tp = O( height ), 但最坏时会退化到链表，复杂度 as O( N ).

- 尽量把它控制成完全二叉树

### 1.1 定义

![1-1](..\image\2025-11-09-16-03-47.png)

- 如果二叉树 T 是一个 AVL 树，则其左右孩子树 $T_l$​ 和 $T_r$​ 也都应该是 AVL 树，且有 $BF(T_p​)∈{0,±1}$

> 说的通俗一些就是，AVL 树的每一个点都平衡，而平衡与否取决于节点的两个孩子树层数之差是否超过 1。

- tip : 空树的高度为-1

### 1.2 构建AVL 

- 对失衡节点使用左旋/右旋操作

- 插入一个节点后，只会影响插入位置到根节点这条路径上的节点的BF值

- 找父节点的操作：应该要在数据结构内加上一个记录父节点的指针

局部调整解决了全局问题——**插入新节点前**和**进行旋转后**，局部子树高度不变，那么往上的全部节点的BF值都可维持不变

## 2. Splay tree（伸展树）

- 均摊复杂度

- 动态调整：防止O(N)的节点被连续访问M次，而导致总复杂度很大

- 类似于输入法对常用词位置的调整。也就是说，每次访问（查找、插入）的节点都会被提升到根节点。

**插入、删除、查找的均摊成本都是$O(\log N)$**

将最近访问的节点旋转到根节点

### 2.2 Deletion

按照BST，删掉根节点后将左子树中的最大点或右子树中的最小点移到根节点。

## 3.3 势能分析

取势能函数太玄学了。学会怎么检验势能函数的有效性即可。

![1-10](..\image\2025-11-09-16-20-09.png)

其中D_i表示第i步操作后数据的状态。c_hat是摊还代价。那么我们可以用摊还代价来估计总操作的实际代价。而为了满足这个等价，我们要让$\Phi(D_n)-\Phi(D_0)>0.$

![](../image/2026-01-01-22-30-55.png)

**总之，让代价大的那一步势能下降，其他普通步骤势能上升。同时保证终止状态$\Phi(S_n)-\Phi(S_0) \ge 0$，就可以了。**

**分析splay tree的均摊复杂度**

对 Splay 的担忧其实就集中在：害怕它可能会调整非常多次，因为它每 access 一个 node，就会把它调整为根。如果一次调整了太多下，就完蛋了。所以我们希望调整很多次的操作，能够让势能降低。

我们都知道把一个 node 调整上去会把整个树差不多变平衡，或者说它会把 node 到根的这条链及其子树变得比较平衡。

所以我们可以把势能函数设计为：平衡的时候势能比较小，在退化成链的时候势能比较大。这样我们调整的次数多，那么让势能降低的也多，这样均摊就好了！

定义势能$\Phi(D_i)=\Sigma_i^n\log\phi(i)$

其中，$\phi(i)$表示以i为根节点的子树的大小（总结点数,含根节点i）
