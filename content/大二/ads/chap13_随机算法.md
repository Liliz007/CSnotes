# 1.Intro : 什么是随机？

## 1.1 平均情况分析(Average-Case Analysis)

想象一下，我们有一台性能稳定的汽车 **（一个确定性算法）**。它的性能好坏，完全取决于路况（算法的输入）。如果路况总是很好（**随机生成的好输入**），那这台车跑得就很快。但如果路况很差（最坏情况输入），它就可能堵在路上动弹不得。

这就是 **平均情况分析： 世界是随机的** —— 我们假设算法的输入是随机生成的，并分析一个传统确定性算法**在这些随机输入下的期望表现**。

这种分析的优点是能告诉我们算法在“通常”情况下的表现。但它有一个巨大的弱点：**它依赖于对输入分布的假设** 。如果现实世界中的输入不符合我们假设的随机分布，那么分析结果就毫无意义。攻击者**可以特意构造一个“最坏情况”的输入** （不随机） ，让我们的算法性能急剧下降。

## 1.2 随机算法(Randomized Algorithms)

现在我们不对路况做任何假设。现在，车在每个路口都会随机选一条路走（即使某一次选择可能很糟糕）。从期望上来看，它总能避开最拥堵的路线。

这就是随机算法的核心思想： 算法是随机的 —— 算法在执行过程中会做出一些随机决策（比如抛硬币）。我们分析的是，**对于任意给定的、甚至是“最坏”的输入，算法的期望表现。**

这样，**随机性就掌握在我们自己手中**（设计算法），而不依赖于外界的随机输入。无论输入有多么“恶意”，我们的算法都能通过内部的随机选择，大概率地避免最坏情况的发生。这就赋予了算法一种强大的鲁棒性。

# 2.Why Use Randomization?

引入随机性听起来似乎让算法变得不可靠了，但实际上它带来了诸多好处，甚至在很多场景下是必不可少的。

## 2.1 性能与正确性的权衡

算法分类：
1. 蒙特卡洛算法：以绝对的高性能，给出高概率正确的答案。
2. 拉斯维加斯算法：保证答案永远正确，但是运行时间随机，只保证它的期望时间是高效的。

## 2.2 对称性破缺(Symmetry-breaking)

在分布式系统中，想象有两个完全相同的进程需要竞争同一个资源。如果它们的行为是确定性的，它们可能会永远同步地尝试、失败、再尝试、再失败，陷入死锁。引入**随机的等待时间** 可以有效地打破这种对称性，让其中一个进程获得资源.

在很多情况下，对于同一问题，随机算法的设计和实现比确定性算法要简单得多。

# 4. CASE1:招聘问题，The Hiring Problem

## 4.1 Description

* scene：你需要通过猎头公司招聘一名新的办公室助理。
* 流程：猎头公司每天推荐一位candidate，总共有N位，持续N天。
* 决策：面试后，如果你觉得这位候选人比你当前雇佣的助理更优秀，你就会换成他；如果你觉得不如当前的，就什么都不做。为了简化问题，我们假设**没有两位候选人的能力是完全相同的** 。
* 成本：包括面试成本和雇佣成本
  * 面试：$C_i$，每次面试都要支付，较低
  * 雇佣：$C_h$，每次雇佣新人时要支付，且$C_h >> C_i$
* 目标：分析整个过程的总成本。由于面试成本是固定的，因此我们希望能最小化雇佣成本，也就是最小化雇佣次数。

## 4.2 朴素的确定性算法

逐个比较过去即可
```c
// 伪代码
int Hiring(Candidate C[], int N) 
{
    // 为了方便，我们假设一个能力值为0的虚拟候选人0作为初始员工
    int best_so_far_id = 0;
    int best_so_far_quality = 0; // 假设质量是数值，越高越好
    
    for (int i = 1; i <= N; i++) {
        // 面试第 i 位候选人，产生面试成本 Ci
        int current_quality = interview(C[i]); 
        
        if (current_quality > best_so_far_quality) {
            // 发现一个更好的人，雇佣他！产生雇佣成本 Ch
            best_so_far_quality = current_quality;
            best_so_far_id = i;
            hire(C[i]);
        }
    }
    //这里返回了最好的人的序号
    return best_so_far_id;
}
```

**成本分析**

1. 最好情况：最牛的人第一天就来了。只雇佣一次。$N*C_i+C_h$
2. 最坏情况：候选人按照能力严格递增的顺序来，造成每次都雇佣。$O(N*C_i+N*C_h)$。由于$C_h$很大，这个成本是无法接受的

这个最坏情况是由输入的顺序决定的。如果有人能恶意安排候选人的顺序，我们的成本就会非常高

## 4.3 平均情况分析

现在，我们做一个美好的假设：这N位候选人是以完全随机的顺序出现的。也就是说，任何一种排列顺序的概率都是$\frac{1}{N!}$ under this assumption,我们计算期望的雇佣次数$E(M)$

我们用一个强大的工具——**指示器随机变量** (Indicator Random Variables)，也就是一个标识hired or not的变量。

* 设X是我们雇佣的总次数，也就是M
* 定义N个指示器随机变量$X_1,...,X_N$.其中

![](../image/2025-12-08-20-58-21.png)

(有点伯努利实验的意思了)

那么总的雇佣次数$X=\Sigma_{i=1}^N X_i$.由期望的线性性，有

$$
E(X)=E(\Sigma_{i=1}^N X_i)=\Sigma_{i=1}^N E(X_i)
$$

由0-1分布，$E(X_i)=Pr(第i位候选人被雇佣)$

现在需要分析Pr(第i位候选人被雇佣)是多少。

第i个人被选上的充要条件：他比前面i-1个人都优秀。由于我们假设顺序随机，因此前i个人中，最优秀的那个出现在第i个的概率是$\frac{1}{i}$

从而总的期望雇佣次数为$E(X)=\Sigma_{i=1}^N \frac{1}{i}$

![](../image/2025-12-08-21-06-22.png)

* 相对于$ln(N)$，$\gamma$和$O(1/N)$都是小项，直接近似掉。
* 这个期望总成本是很好的，例如，如果有10000个候选人，ln(10000)=9.2，我们平均只需要雇佣9-10次，而不是最坏情况的10000次。
* 这个分析的缺陷在于它依赖“输入是随机的”这一假设。如果不是随机的，那又要赤石了。

## 4.4 随机算法：自己创造随机性！

我们不再期待输入是随机的，我们自己在算法内部将其随机化。

```c
// 伪代码
int RandomizedHiring(Candidate C[], int N) {
    // 关键步骤：在开始之前，随机打乱候选人数组C！
    RandomlyPermute(C); // 这步是新加的
    
    // 后面的代码和朴素算法完全一样
    int best_so_far_id = 0;
    int best_so_far_quality = 0;
    
    for (int i = 1; i <= N; i++) {
        int current_quality = interview(C[i]);
        if (current_quality > best_so_far_quality) {
            best_so_far_quality = current_quality;
            best_so_far_id = i;
            hire(C[i]);
        }
    }
    return best_so_far_id;
}
```

我们只是在最开始增加了一步 RandomlyPermute。这一步的意义是革命性的——我的命运操之在我！

* 我们不再依赖于输入的分布。无论输入的候选人顺序是按能力递增、递减还是任何其他恶意构造的顺序，经过我们第一步的随机打乱后，它都会变成一个随机排列。
* 因此，对于任何输入，后续算法所面对的序列都是随机的。这意味着我们刚才的平均情况分析，现在变成了对这个随机算法在任何输入下的期望性能分析。
随机化这一步，将“运气”从外部世界拉到了我们自己手中。我们保证了算法的期望性能，使其不再受恶意输入的攻击。

## 4.5 随机排列的实现

### 4.5.1 基于排序的排列：Permute By Sorting

1. 为数组中的每个元素A[i]分配一个**随机的优先级P[i]**
2. 根据这些优先级对A重排

```c
// 伪代码
void PermuteBySorting(Element A[], int N) {
    for (int i = 1; i <= N; i++) {
        // 分配一个足够大的范围内的随机数以避免冲突
        A[i].priority = rand() % (N*N*N);
    }
    // 使用任何 O(N log N) 的排序算法，根据 priority 排序
    Sort(A, based_on_priority);
}
```

# 5. CASE2:在线招聘问题(Online Hiring Problem/Secretary Problem)

招聘问题的变种

## 5.1 Description

* 规则变化：依然是从N个随机排列的人中选出最好的那个
* 核心constraints:
  * 从头到尾只能雇佣一个人。
  * 对于每个候选人，面试后你必须立即决定是否雇佣他。如果决定不雇佣，你以后就再也不能回头选择他了。
  * 一旦雇佣一个人，过程立即结束
* 目标：设计一个策略，使得你成功雇佣到最好的那一位候选人的**概率最大化**。

>就是以前看的寓言故事中，路过一片麦田，摘一朵最大的麦穗的问题。

## 5.2 Best Strategy

**steps:**
1. 确定一个参数k，1<k<N
2. 考察阶段：面试前k个候选人，但全都不雇佣。只记住这k个人中能力最强的人，我们记他的能力值为best_quality_in_first_k
3. 选择阶段：从第k+1位候选人开始，只要遇到一个比best_quality_in_first_k更强的人，马上雇佣他，然后quit
4. 如果面试完所有人都没有找到比best_quality_in_first_k更好的人，说明最好的人就在前k个中，已经错过了。但是为了雇到人，只好雇佣第N个人。

```c
// 伪代码
int OnlineHiring(Candidate C[], int N, int k) {
    // 假设 C 已经是随机排列
    int best_quality_in_first_k = -1; // 假设质量为非负数
    // 1. 考察阶段
    for (int i = 1; i <= k; i++) 
    {
        int quality = interview(C[i]);
        if (quality > best_quality_in_first_k) 
        {
            best_quality_in_first_k = quality;
        }
    }
    
    // 2. 选择阶段
    for (int i = k + 1; i <= N; i++) 
    {
        int quality = interview(C[i]);
        if (quality > best_quality_in_first_k) 
        {
            return hire(C[i]); // 立即雇佣并返回
        }
    }
    
    // 3. 策略失败，被迫雇佣最后一人
    return hire(C[N]);
}
```

**我们需要分析：**
1. for a given k,我们成功雇佣到最佳人选的概率？
2. 如何确定最好的k来使此概率最大化？

## 5.3 概率分析

* 记S=“成功雇佣到最佳人选”
* 记$S_i=$ “第i位候选人是最佳人选，并且我们成功雇佣到了他”
* 显然，$S=\bigcup_{i=k+1}^N S_i$.因为如果最佳人选在前k位，我们必然错过他。又由于这些$S_i$是互斥的，我们有$Pr(S)=\Sigma_{i=k+1}^N Pr(S_i)$

现在我们计算$Pr(S_i)$.事件$S_i$发生的条件分为两个事件：
* 事件A：第 i 个人是全部人中最好的
* 事件B:我们没有在第k+1到i-1之间雇佣任何人（没有猴急）

A与B是独立的，因为：（意会一下！）

![](../image/2025-12-08-21-38-53.png)

计算概率：

* Pr(A):由于是随机排列，最佳人选出现在任意位置的概率都相同，为$1/N$
* Pr(B):从k+1到i-1中的人都不比前k中最强的人强。也就是说，前i-1个人中，最强的人出现在前k个人中。此概率为$\frac{k}{i-1}$

因此$Pr(S-i)=Pr(A\bigcup B)=Pr(A)Pr(B)=\frac{1}{N}*\frac{k}{i-1}$

总的成功概率：$Pr(S)=\frac{k}{N} \Sigma_{i=k+1}^N \frac{1}{i-1}=\frac{k}{N} \Sigma_{i=k}^{N-1} \frac{1}{i}$

# 6. 随机快排

关键问题：划分的均匀程度。若极不均匀，会从$O(NlogN)$退化到$O(N^2)$

为什么退化：每次都选到组中的最大（最小）值，则递推式为$T(N)=T(N-1)+\Theta(N)$.(因为每层都要遍历所有元素，与pivot比较)。展开后最终得到$O(N^2)$

## 6.1 优化：随机选择pivot

1. Central Splitter : 定义一个“好”的pivot为中心分割点，如果它分割的结果中小的那一part的大小不少于N/4.
2. 第i次能选到central splitter的概率$\Sigma_{k=1}^i i*\frac{1}{2^k}$， i 的期望值是2.

按照这种划分，最大递归深度就是$\log_{3/4}N$

**Type j**: 子问题S是type j的，如果$N(\frac{3}{4})^{j+1} \le |S| \le N(\frac{3}{4})^j$

这样可以限制住每一层子问题的总成本为$O(N)$.

因此总的期望运行时间$O(NlogN)$.
