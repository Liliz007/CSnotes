# 1. Intro

为什么我们不能直接在磁盘上运行像快速排序这样的高效内部排序算法呢？

在内部，满足访问任意一个元素a[i]的时间是O(1)

但在disk，访问元素过程如下：
1. find the track（先找到特定的盘片cylinder）
2. find the sector
3. find a[i] and transmit

找到数据花费的时间比内存访问慢了几个数量级。快排的特点是频繁地进行随机访问，每次访问都要进行一次I/O，这是device dependent的，比计算成本大得多了

从而，我们希望**最小化disk I/O的次数**

引入一个经典工具：Merge Sort

简化假设：
* data存在磁带(Tapes)上，其只能进行顺序读写
* 我们至少有3个tape drives

# 2. 简单做法

假设内存只能放M=3个数据，总共有13个数据（存储在Tape上）

![](../image/2025-12-23-13-55-22.png)

* 数据量为N，内存大小为M，段数为N/M。每次归并段数都减少一半。
* merge在内存中进行。
* 只关心I/O（跟内存中计算比起来慢得多）

想要优化的话，（但是N和M都不能改）应该动哪里呢？——重新审视一下挑战：

1. 访存时间：问了多少次数据。访存是最慢的。
   * run : 每组排好序的数据称为一个run。即一个有序小顺串
   * pass : 将所有数据读过一遍的称为一个pass。也就是合并一回，顺串数变成原来的1/k的完整过程。
2. 读写数据块的时间
3. 内部排序的时间
4. 内部合并时间: 在合并阶段，从输入缓冲区向输出缓冲区合并records的CPU时间。

通常情况下，**I/O时间（寻道+读写）远大于CPU处理时间**。

一个好消息是，现代计算机可以**并行执行 I/O 和 CPU 处理**。
>当CPU在处理当前内存中的数据时，可以预先将下一块数据从磁盘读入缓冲区。

基于以上分析，我们的**优化目标**变得非常清晰：
1. 减少总趟数 : 这是最核心的优化点。因为一趟要把所有数据读一遍，要等待磁带移动，很慢
2. 优化顺串合并（Run merging）: 提高合并效率，比如使用更少的磁带。
3. 优化缓冲区管理（Buffer handling for parallel operation）: 实现I/O和CPU的并行，隐藏I/O延迟。
4. 优化初始顺串生成（Run generation）: 生成更长的初始顺串，从源头上减少顺串数量。

接下来，我们将逐一探讨实现这些目标的策略。

## 2.1 优化1：减少趟数—— k-way merge

每次合并k个小段，这样合并趟数的表达式就变成：

$\log_k(段数)$

加上初始的一趟，总趟数就是$\ceil{\log_k(N/M)}+1$。

k 路合并有一个实现上需要注意的点，因为我们是 k 个顺串要合并，因此我们需要不断的在 k 个元素中选取最小值放到输出的磁带上，这个操作可以使用优先队列来实现。

### 多路合并改进：多相合并

为了优化多路合并的tape数成本，我们考虑多相合并。磁带成本可以从$2k$减少到$k+1$.

其实就是把T1上的runs分配到T2和T3上，merge，然后回归T1。就是一个搬来搬去的过程。每次都输出给T1。但是这种方法需要频繁copy runs

![](../image/2025-12-23-14-27-09.png)

>如图，有3盘磁带T1,T2,T3，T1上有34个runs。我们可以给T2和T3分别放入17个runs，然后合并到T1上，得到一盘17个runs的磁带和两个空磁带。
>因为要用合并，那么又要重复初始时的操作，将T1上的runs分一些到T2，再拿这俩合并到T3。
>这样的话，每次合并都要进行额外的复制操作，复制又要访存，也就是移动磁头，这样很昂贵。
>对于上例，我们总共需要的操作数：1初始+5合并+？复制

**改进——不均匀划分** ：要划分成斐波那契数，最后可以合并成一段。

>如果不用斐波那契，仍可能出现上面的要额外复制或长短不对齐导致浪费的情况。

如果是k-way merge 就使用k阶斐波那契数，def如下：
$$
F_N = F_{N-1}+F_{N-2}+...+F_{N-k}

## 2.2 优化2：buffer与并行操作

初始想法：
1. 在实现外部排序时，我们通常会分块读取数据，而不是每次比较后立即将一个元素写入磁盘。
2. 这样做会导致每次比较后都需要等待磁盘处理，耗费大量时间。
3. 在2路合并中，内存应划分为2个输入缓存区和1个输出缓存区。输入缓存区用于存放从磁盘读取的数据，两个输入缓存区的数据比较后，结果暂存于输出缓存区。当输出缓存区满时，再一次性写入磁盘。

上述方法的问题：
当输出缓存区写回磁盘时，内存中的操作会暂停。

解决：
【输出】我们将输出缓存区拆分为两个。当一个缓存区满并写回磁盘时，另一个缓存区继续接收数据，实现并行处理——一个在内存中操作，另一个进行I/O交互。
【输入】输入缓存区也类似。如果只有2个输入缓存区，当数据比较完时，我们必须等待新数据从磁盘读入。因此，我们将其进一步划分为4个输入缓存区。当两个缓存区的数据正在**比较**时，另外两个缓存区可以**并行读取**新数据。

这样，CPU和I/O设备可以像流水线一样协同工作，只要I/O速度能跟上CPU处理速度，I/O的等待时间就可以被大部分隐藏。

**【k-路归并的缓冲需求】** 为了实现完全的并行操作，对于一个k-路归并：

* 我们需要 k 个输入流，每个流配备双缓冲（一个存比较结果一个读取），共需 2k 个输入缓冲区。
* 我们需要 1 个输出流，配备双缓冲（一个接收一个写入），共需 2 个输出缓冲区。

总共需要2k+2个缓冲区。
