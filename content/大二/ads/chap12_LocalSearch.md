# 1. Intro

想象一下，你被蒙上眼睛，放在连绵起伏的山脉中，你的任务是找到山脉的最低点（全局最优解）。你该怎么办？一个很自然的想法是：在你的脚下感受一下周围哪个方向是向下走的，**然后朝着最陡峭的向下方向走一步**。你不断重复这个过程，直到你发现无论朝哪个方向走，地势都是向上的。这时，你就到达了一个“山谷”。

这个“山谷”就是我们所说的**局部最优解 (local optimum)**。它不一定是整个山脉的最低（**全局最优解, global optimum**），但它确实是它附近区域的最低点。我们按照这种思路设计算法，它显然是可以在有限步内结束的——因为解空间是有限的，且我们每一步都在改进，在缩小可取范围。

当然，我们希望这个局部最优点就是全局最优点。

**最陡峭的方向：梯度方向**。后续说的梯度下降就是由此而来。

## 1.1 术语——搭建形式化框架

让我们用更严谨的语言来定义这个过程。局部搜索算法通常包含两个核心部分：**“局部”** 和 **“搜索”** 。

### 局部(Local)

1. 邻域(neighnorhood): 对于解空间中的一个可行解S，我们定义一个与之相邻的解的集合$N(S)$，称为S的邻域。相邻通常指对S进行微小的改动而得到。
2. 局部最优：若S在其邻域$N(S)$中最优，他就是一个局部最优解。

### 搜索(Search)

1. 起始: 从一个初始的可行解开始。
2. 迭代: 在当前解的邻域中寻找一个更好的解。如果找到了，就移动到那个更好的解，并继续这个过程。
3. 终止: 当在当前解的邻域中找不到任何比它更好的解时，搜索停止。此时，我们就说算法**收敛到了一个局部最优解** 。

## 1.2 邻域关系与梯度下降算法

我们来形式化地定义“邻域”。

1. 邻接关系(~):如果解$S'$可以通过对解$S$进行一次小的修改得到，我们就说$S'$是$S$的一个邻接解(neighboring solution)，记作$S'$ ~ $S$
2. 邻域：解S的邻域$N(S)$是所有与S邻接的解的集合。即$N(S)=\{S'|S$~ $S'\}$

最简单、最直观的局部搜索算法就是**梯度下降 (Gradient Descent)**, 或称为**爬山法 (Hill Climbing)**。它的策略是“贪心”的：在每一步都选择邻域中最好的那个解。

下面是梯度下降算法的pseudo code

```c
SolutionType Gradient_Descent()
{
    // 从一个可行的初始解 S 开始
    S = GenerateInitialSolution();
    
    // 计算初始解的成本
    MinCost = cost(S);

    while (true) {
        // 在 S 的邻域 N(S) 中找到最好的邻居 S'
        S' = Search_Best_In_Neighborhood(N(S)); 
        // 计算 S' 的成本
        CurrentCost = cost(S');       
        // 如果 S' 比 S 更好 (成本更低)
        if (CurrentCost < MinCost) {
            // 更新最优解和最低成本
            S = S';
            MinCost = CurrentCost;
        } 
        else 
        {
            // 如果邻域中没有更好的解，说明到达局部最优，退出循环
            break;
        }
    }
    
    // 返回找到的局部最优解
    return S;
}
```

* 注意上面S'是N(S)中的**最好的邻居**

# 2. CASE1: 顶点覆盖(VC)

这是一个NP-hard问题

## 2.1 Description

![](../image/2025-12-01-16-18-08.png)

* 决策问题版本回答“是”/“否”。是NPC的（由子团问题规约得到）
* 优化问题版本是找出一个最优解，是NP-hard的

我们的目标是解决这个优化版本，即找到最小的顶点子集。

## 2.2 使用Local Search

**1. 可行解集** (Feasible Solution Set, FS): 所有的顶点覆盖都是我们的可行解。

**2. 成本函数** (Cost Function): 对于一个可行解（一个顶点覆盖）S，其成本就是它包含的顶点数量，即 $cost(S) = |S|$。我们的目标是最小化这个成本。

**3. 邻域关系(S~S')** : 如何定义邻域？一个简单的方法是：每次只修改一个顶点。但是，如果我们随意添加或删除一个顶点，得到的新集合可能不再是一个顶点覆盖，也就不是可行解了。一个更巧妙的定义是——
1. 删除点：从一个VC中删除一个点V，如果得到的新集合**S' = S-{V}仍然是一个VC**，则说S'是S的一个邻居
2. 添加点：S'类似上面的定义。但这样会增加成本，不适用我们的梯度下降算法。
3. 也就是说，定义S'时我们不考虑：**【1】增加点** **【2】删除点后不是VC** 这两种情况

**4. 搜索策略：** 很简单的迭代
   1. 起始：一个简单且保证是可行解的初始方案是 S = V，即选择所有顶点。这显然是一个顶点覆盖，尽管成本很高。
   2. 迭代：在当前S中尝试删除每一个点v。如果得到的真邻居S'的代价更小（肯定啊都删了一个点了），就找到了一个更好的解。我们可以选择第一个找到的，也可以遍历所有可删除的顶点，选择使成本下降最多的那个。

**总结：**
1. 每个顶点覆盖S最多有|S|(<=|V|)个邻居解
2. 搜索过程：从 S = V 开始，不断地尝试删除一个顶点，**只要删除后仍然是顶点覆盖，就执行这个删除操作** ，直到无法再删除任何顶点为止。

## 3.2 讨论

我们继续考虑困在局部最优的情况。除了上面的case，一个经典的例子是旅行商问题 (TSP)。

1. 问题: 找到一条访问所有城市一次并返回起点的最短路径。（注意，TSP对应的是完全图）
2. 局部搜索框架:
   * 解: 一条合法的路径（一个城市的排列）。
   * 成本: 路径总长度。
   * 邻域: 一个常用的邻域是 2-opt。即，选择路径中的两条边 (a, b) 和 (c, d)，删除它们，然后用 (a, c) 和 (b, d) 重新连接，从而得到一条新的路径。

3. 失效情况: 2-opt 局部搜索很容易陷入局部最优。可能换边之后，光看权可以找到一个看起来还不错的环路，但它可能存在一些交叉（一个点访问多次），而要解开这些交叉可能需要同时改变3条或更多的边（即需要一个更大的邻域），而 2-opt 无法实现这一点。

# 4. 逃离局部最优：模拟退火

既然梯度下降这么容易“卡住”，我们该如何改进呢？一个核心思想是：**允许偶尔接受一个更差的解** ，以求“跳出”当前的局部最优，去探索更广阔的解空间。也就是说：允许翻越山脊去看另一边。

## 4.1 Metropolis 算法

>【简介】：Metropolis接受准则由Nicholas Metropolis等人于1953年提出，是马尔可夫链蒙特卡洛（MCMC） 和模拟退火算法的核心组成部分。

Metropolis 算法引入了概率。
* 如果邻居 S' 比当前解 S 好，我们总是接受它。
* 如果邻居 S' 比当前解 S 差（成本更高），我们以一定的概率接受它。

这个概率由Boltzmann分布给出：
$$
P_{accept} = e^{-\Delta E/(kT)}
$$

* $P_{accept}$是接受概率
* $\Delta E = cost(S')-cost(S)$:是成本的增量（此处为正数，因为是更差的解）
* $T$: “温度”
* $k$: 是玻尔兹曼常数（在算法中可以设为1）

**直观理解：**

* $\Delta E$越小，即成本差值不大，接受的概率越大
* 温度$T$越高，接受的概率越大。也就是说在高温时比较有激情，倾向于探索，甚至接受很差的解

**pseudo code如下**

```c
SolutionType Metropolis()
{
    // 定义常数 k 和 T
    Define constants k and T;

    // 从一个可行解开始
    S = GenerateInitialSolution();
    MinCost = cost(S); // 记录遇到的最好成本

    while (not_stopped) {
        // 从邻域中随机选择一个邻居
        S' = Randomly_chosen_from(N(S));
        CurrentCost = cost(S');

        if (CurrentCost < cost(S)) 
        { // 注意这里是和 cost(S) 比较
            // 如果更好，总是接受
            S = S';
            if (CurrentCost < MinCost) MinCost = CurrentCost;
        } 
        else 
        {
            // 如果更差，计算成本差
            delta_cost = CurrentCost - cost(S);
            // 以一定概率接受
            if (random_uniform(0, 1) < exp(-delta_cost / (k * T))) {
                S = S';
            }
        }
    }
    return best_solution_found; // 返回整个过程中遇到的最好的解
}
```

>Note: random_uniform(0,1) < p
>是说生成一个(0,1)之间的随机数，若其小于p就接受。其实也就等价于以概率p接受。


## 4.2 模拟退火(Simulated Annealing)

如果温度不变，算法同样可能由于过于有探索欲而错过全局最优解。从而我们要设计一个**温度变化**的策略。

模拟退火是 Metropolis 算法的升级版。它模拟了物理中金属退火的过程：
1. 将金属加热到高温，然后非常缓慢地冷却。在高温时，分子可以自由移动（对应算法中的广泛探索）
2. 随着温度降低，分子逐渐稳定下来，形成能量最低的晶体结构（对应算法收敛到最优解）

关键在于**冷却策略** (Cooling schedule)：温度 T 不再是固定的，而是随着时间的推移慢慢降低。$T=T_1,T_2,...,其中T_1 > T_2 > T_3 ...$

**冷却过程：**
1. 初期【高温】：T很大，$exp(-\Delta E/kT)$接近1，算法几乎会接受所有移动，类似于随机游走，从而广泛探索解空间。
2. 中期【中温】：T 减小，算法开始**倾向于接受好的移动**，但仍有一定机会跳出局部最优。
3. 末期【低温】：T 趋近于0，$exp(-ΔE/kT)$ 趋近于0，算法几乎只接受好的移动，行为类似于梯度下降，从而**在当前找到的“好区域”内进行精细搜索。**

**理论上可以证明：** 如果冷却得足够慢，模拟退火算法能以概率1收敛到全局最优解。

# 5. CASE2：Hopfield神经网络

局部搜索在很多领域都有应用，我们来看一个来自神经网络的例子：Hopfield 网络。

## 5.1 问题建模

想象一个网络，由节点和带权重的边组成。

1. 图：$G=(V,E)$，边的权重$w_e$可正可负
2. 节点状态：每个节点$U$有一个状态$s_u$，取值为±1
3. 约束：
   1. 如果边$e=(u,v)$的权重为负，他表示希望u和v状态相同($s_u=s_v$)
   2. 如果边$e=(u,v)$的权重为正，他表示希望u和v状态相异($s_u ≠ s_v$)
   3. 权重的绝对值表示这个约束的**强度**
4. 输出：我们要找一个网络的构型 (configuration) S，也就是给每个节点都**分配一个状态 +1 或 -1** ，使得整个网络“尽可能和谐”（即**满足尽可能多的、权重大的约束**）。

![](../image/2025-12-01-20-30-41.png)

有些网络是不存在满足所有边的要求的构型的。如上图，权重都为正，说明他们仨想两两互异，但一共就两种状态，所以是不可能的。

**In this case,我们希望能找到一个“尽可能好”的解**

## 5.2 术语——形式化定义

**1.好边/坏边**

* 在构型S中，如果一条边e=(u,v)的约束被满足，即$w_e s_u s_v < 0$（此式子概括了两种情形），则称其为好边(good edge)
* 否则，称之为坏边(bad edge)

**2.满足的节点(satisfied node)**

* 一个节点u，与它**相连的good edge的权重绝对值之和 >= bad edge的权重绝对值之和（绝对值），则称u是满足的。**
* 数学上，这等价于$\Sigma_{\{u|e=(u,v)∈E\}}w_e s_u s_v \le 0$.因为好边的$w_es_us_v$是负数，坏边是正数，总和小于等于0也就是说好边的权重和大于等于坏边的（绝对值）。

**3.稳定构型(stable configuration)**

如果一个构型中所有节点都满足，则称此构型是稳定的。

其实是减弱了要求。满足不了边就满足所有点。

![](../image/2025-12-01-20-47-54.png)

* 上图中白点state=1，黑点state=-1. 此图是一个稳定构型。

**【问题】Hopfield 网络是否总存在一个稳定构型？如果存在，如何找到它？**

## 5.3 状态翻转算法(State-flipping)

```c
ConfigType State_flipping()
{
    //从一个任意的初始构型S开始
    Start from an arbitrary configuration S;
    while ( ! IsStable(S) ) //这个图不稳定
    {  //任意找一个不满足的节点u
        u = GetUnsatisfied(S);
        //翻转u的状态
        s_u = - s_u;  
    }
    //返回找到的稳定构型
    return S;
}
```

过程例子：

![](../image/2025-12-02-14-39-51.png)


**【问题】这个算法总是能终止吗？会不会一直运行下去？**

**【答案】是的，这个算法总会终止。 我们可以用一个非常漂亮的数学方法来证明它——势函数法 (Potential Function Method)。**

### 终止性证明

**【定理】：** 此算法最多在$W=\Sigma_{e∈E}|w_e|$次迭代后，会终止于一个稳定构型。

**【证明】** 我们来定义一个“衡量系统有多好”的函数，称为势函数$\Phi(S)$。 让$\Phi(S)$等于当前构型 S 中所有**好边** 的权重绝对值之和:
$$
\Phi(S)=\Sigma_{e\ is\ good}|w_e|
$$

现在，我们分析将一个不满足的节点u翻转后，势函数发生的变化。设新构型为S'

1. 与u相连的边：
   1. 对于任意一条边e=(u,v)，$s_u s_e$会变号
   2. 也就是说所有原来与u相连的good->bad，bad->good。从而由“满足”的定义可知u现在变成了满足的点
2. 与u不相连的边：保持原状态

所以$\Phi(S')=\Phi(S)-\Sigma_{e1\ is\ good\ in\ S}|w_{e1}|+\Sigma_{e2\ is\ bad\ in\ S}|w_{e2}|$

现在，关键的一步来了。我们为什么选择翻转一个不满足的节点 u？ 根据定义，节点 u 不满足，意味着与它相连的 **坏边权重之和严格大于好边权重之和。** 那么翻转后好边权重必增加。即：
$$
\Sigma_{e\ is\ bad\ in\ S}|w_e| > \Sigma_{e\ is\ good\ in\ S}|w_e|
$$

从而就有$\Phi(S')-\Phi(S) > 0$

由于权重都是整数，甚至可以得出$\Phi(S')-\Phi(S) \ge 1$

从而，**每一次翻转一个不满足的节点，势函数的值至少加1**

这个函数是有上限的，因为$\Phi(S)$的最大值不会超过所有边权重绝对值之和W。因此此算法必然在有限步内终止，终止时获得的构型就是一个稳定构型。

### 与局部搜索的关系

1. 问题：To maximize $\Phi$ (所有好边的绝对值之和)
2. 可取解集：构型
3. 邻域定义：通过翻转某一个S内的节点能够得到的S'的集合

**【定理】** 任意局部最优解都是一个稳定构型。（如果不稳定，就必然存在不满足的点，翻转它之后得到的$\Phi$就会增大，与局部最大矛盾）

**复杂度：** 此算法对N和$log W$是多项式复杂度。（W是总权重的绝对值之和）

![](../image/2025-12-02-14-50-24.png)

W用二进制表示，则位数为$logW$

如果W特别大，则步数上界非常高，可能就不是$n$和$m$的多项式了。

# 6. CASE3：最大割问题(Maximum Cut)

## 6.1 Description

给定一个带正权重的无向图 $G=(V,E)$，你需要将所有顶点 V 划分成两个不相交的集合 (A, B)。一个“割”指的是**连接 A 中顶点和 B 中顶点的边的集合** 。最大割问题的目标是**找到一个划分 (A, B)，使得这个割中所有边的权重之和最大** 。$w(A,B):=\Sigma_{u∈A,v∈B}w_{uv}$

### 与局部搜索的关系

我们可以将最大割问题看作是 Hopfield 网络的一个特例：

1. 将划分 (A, B) 对应于节点状态：A 中的节点状态为 +1，B 中的节点状态为 -1。
2. 一条边 (u,v) 跨越割，当且仅当 u 和 v 在不同的集合中，即$s_u ≠ s_v$。
3. 为了最大化跨越割的边的权重，我们希望满足$s_u ≠ s_v $这个约束。这对应于 Hopfield 网络中的情况。

所以，最大割问题等价于一个**所有边权重都为正** 的 Hopfield 网络，其目标是最大化$\Sigma_{e\ is\ good}w_e$。（组间状态不一致，所以组间皆好边，组内皆坏边）

我们可以使用与 Hopfield 网络相同的状态翻转算法（在这里称为 single-flip）：

1. 邻域: 通过将一个节点从 A 移动到 B，或者从 B 移动到 A，来得到新的划分。（单反邻域）
2. 算法:
   * 从一个任意划分 (A, B) 开始。
   * 只要存在一个节点 u，它的组内边权重和大于组间边权重和(坏和>好和，不满足)，就移动它。移动后，与u相连的good->bad，bad->good，u满足了，其他不变
   * 直到没有节点可以通过移动来增加割的权重时停止。

**Pseudo Code**
```c
ConfigType State_flipping()
{
    Start from an arbitrary configuration S;
    while ( ! IsStable(S) ) {
        u = GetUnsatisfied(S);
        su = - su;
    }
    return S;
}
```
### 复杂度

$O(NW)$

最多检查N个结点，翻转步数上界是W。故复杂度为$O(NW)$

### 近似比

2-近似。

**声明 (Claim):** 对于最大割问题，由 Single-Flip Heuristic 找到的任何一个局部最优划分 (A, B)，其割权重至少是全局最优划分 (A\*, B\*) 的一半。 即： $w(A, B) \ge \frac{1}{2} w(A^*, B^*)$

# 7. 改进局部搜索

## 7.1 如何保证多项式时间？Big-improvement-flip
   * Single-flip 算法的运行时间可能依赖于权重 W。为了让它成为真正的多项式时间算法，我们可以修改策略：不是任何一点改进都接受，而是只接受足够大的改进。
   * Big-improvement-flip: 只选择那些翻转后能让割权重至少增加$\frac{2\epsilon}{|V|}w(A,B)$的节点来翻转

**【定理1】**：算法返回一个$(2+\epsilon)$-近似解。即 $(2+\epsilon)w(A,B) \ge w(A^,B^)$。

**【定理2】**：该算法在$O(\frac{N}{\epsilon}logW)$次翻转后就会终止，这是一个多项式时间算法。甚至是FPTAS

## 7.2 如何获得更好的解？尝试更好的local（邻域）
Single-flip 的邻域太小了，容易陷入质量不高的局部最优。我们可以扩大邻域。

**邻域大小的权衡:**
* 邻域太小: 容易陷入局部最优。
* 邻域太大: 搜索邻域本身的时间开销巨大。

将single flip变为k flip：一次翻转k个节点。邻域大小为$\Theta(N^k)$，（因为$C_N^k=\Theta(N^k)$）但k大了就不行了（指数啊喂）

## 7.3 Kernighan-Lin(KL)算法

![](../image/2025-12-02-15-25-43.png)

一轮进行一系列的节点翻转。在中间结果中选择累积收益最大的那个作为本轮的结果。

邻域指的是在一轮中允许探索的空间，是由(n-k+1)个未锁定节点进行逐个移动得到的解序列。

一轮中的邻域总计算量：
* 第一步计算$O(N)$个节点的增益，然后取最大
* 第二步计算$O(N-1)$
* ...
* 第N轮计算$O(1)$
故总邻域$O((N+1)N/2)=O(N^2)$

邻域足够丰富，但也不太大。
