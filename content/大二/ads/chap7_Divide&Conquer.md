# 1. Intro

分治，正如其名，即“分而治之”。当我们面对一个规模庞大、难以直接下手的复杂问题时，分治策略引导我们将其拆解。具体来说，它遵循一个递归的、三步走的过程：

1. **分解 (Divide):** 将原始问题分解为若干个规模更小、但结构与原问题完全相同的子问题。
2. **解决 (Conquer):** 递归地求解这些子问题。当子问题的规模小到足以轻松解决时（即达到递归的“基例”），便直接求解。
3. **合并 (Combine):** 将各个子问题的解合并起来，最终构筑成原问题的解。

$$时间复杂度公式：T(N) = aT(N/b)+f(N)$$

- $a$：分解后产生的子问题数量
- $N/b$ : 每个子问题的规模
- $f(N)$ : 代表分解problem和merge子问题所用时间



案例：最大子序列之和，merge-sort，quick-sort，树的遍历

# 2.Cases

## 2.1 平面上的最近点对

**问题描述：** 给定二维平面上的 N 个点，请找出其中距离最近的两个点及其距离。 (特殊情况：若两点坐标完全相同，则它们是最近点对，距离为 0)

### 2.1.1 暴力穷举

用组合数，N个点共需枚举这么多对：

$C(N,2) = N(N-1)/2$

从而时间复杂度为：$O(N^2)$

![7-1](image\2025-11-10-21-36-23.png)

但是$O(N^2)$还是太大了，有没有更加简单又强势的方法？

### 2.1.2 分治法

![7-2](image\2025-11-10-21-36-39.png)

1. **分解 (Divide):**
   - 为了有效地“切分”点集，我们首先将所有点按照 x 坐标进行全局排序。
   - 找到所有点 x 坐标的中位数$x_{mid}$，并以此为基准画一条垂直的分割线L。
   - 这条线 L将点集几乎均等地分为左右两个子集：左集 $P_L$和右集$P_R$。

2. **解决 (Conquer):**
   - **递归地**在左子集中寻找最近点对，得到其最短距离$δ_L$。
   - **递归地**在右子集中寻找最近点对，得到其最短距离$δ_R$。
   - 到目前为止，我们已经获得了两个半区内部的最小距离，令$δ = min\{δ_L , δ_R\}$ 

3. **合并 (Combine):**
     - 这是整个算法**最核心、最巧妙**的部分。我们已经有了$\delta$，但真正的最近点对有没有可能**跨越**了分割线 ？也就是说，一个点来自左子集，另一个点来自右子集。
     - 如果存在这样一个“跨界”点对 ，并且它们的距离小于我们已知的 $δ$，那么这两个点必然满足一个重要的几何特性：它们各自到分割线的水平距离都必须小于$δ$ 。
     - 因此，我们的注意力可以聚焦于一个以L为中心、宽度为 $2δ$ 的狭长“条带” (strip) 区域。所有可能构成更短距离的跨界点对，都必须位于这个条带内。
     - 接着，对y坐标排序，在y坐标下做δ限制，从而对每个点，只需搜索$δ*2δ$大小的矩形邻域（对每个点$(x,y_0)$，考察$y>y_0$的那边的点）

扫描区域如下图所示：（两条褐色线的间距为$\delta$）

![](../image/2026-01-05-17-18-01.png)

![](../image/2026-01-05-17-18-21.png)

伪代码表示：
```c
/* points are all in the strip */
/* and sorted by y coordinates */
for ( i = 0; i < NumPointsInStrip; i++ )
    for ( j = i + 1; j < NumPointsInStrip; j++ ) 
        if ( Dist_y( Pi , Pj ) > δ )
	break;
        else  if ( Dist( Pi , Pj ) < δ )
	 δ = Dist( Pi , Pj );
```

#### Observation

所选区域中的点数有限。

![](../image/2026-01-05-20-11-18.png)

* 无论如何，我们可以得到结论，在这种情况下，对于每一个选定的 $p_{li}$​​，寻找其可能导致答案更新的点的复杂度都是常数级的。
* 而枚举这些“选定点”，也就是枚举$p_{li}$​，其复杂度（撑死）是 O(N)。故combine的复杂度就是f(N)=O(N)

于是我们能得到这个分治的时间复杂度计算递推公式：

$T(N) = 2T(N/2) + O(N) = O(NlogN)$

其中，T(N/2) 是左右子区域内处理的复杂度；O(N)是计算跨过中线的最小距离的复杂度

在这个case中，可见分治法分为三个步骤：**分解，解决（子问题），合并** 

对于这题，分解和合并的复杂度包含在$O(N)$中，解决子问题复杂度为$2T(N/2).$

# 3.复杂度分析

分治算法的代价，不仅取决于分解的形式，还要看$f(N)$的大小。

$if \ \ T(N) = 2T(N/2) + cN^2$

$= 2[ 2T(N/2^2) + cN^2/2^2 ] + cN^2$

$
= 2^2 T(N/2^2) + cN^2(1+1/2)$

$= ……$

$
= 2^k T(N/2^k) + cN^2(1+1/2+…+1/2^{k-1} )
$

$= O( N^2 )$

下面讨论一些计算复杂度的方法。递推式形如：

$$T(N) = aT(N/b)+f(N)$$

前提：
- 不考虑 (N/b) 是否为整数，全部近似为整数。
- always assume $T( n ) = Θ( 1 )$ for small n 。 即划分得足够小时，操作为常数级（这也就是我们划分的终点）
- $T(N/b)$是“解决”，$f(N)$是分解及合并的总复杂度

## 3.3 主方法 master method

### 3.3.1 👺master theorem，主定理

目标：从表达式看出解决总子问题(conquer)和合并(combine)谁占主导，即谁更昂贵。

**Form 1** **（要求会推导）**

![](image\2025-11-10-17-23-38.png)

- regularity condition（正则性定理）是指 $af(N/b)<cf(N)$

这个定理保证了当前层的分割合并总代价不会被下一层超过，确保递归的正确性。

>其实是好理解的。分解的子问题到最底层是$a^{\log_bN}=N^{\log_ba}.$ 我们判断每层分解是根占主导还是叶占主导。也就是看f(N)和$N^{\log_ba}$谁增长更快。

![](image\2025-11-10-17-23-52.png)

这图中写错了，下面这$\Omega$里面是＋ε。

Ω关系：$M = Ω(N)$，表示M再小也不会比N小，N是M的严格下界。显然$\log N$并不是多项式级的$N^{\epsilon}$的上界。

**我明白理解方法了！同时也可以记忆**

按照递归树那样划分到底层，叶子数为$a^{\log_bN}$，即$N^{\log_ba}$。从而conquer（处理子问题）的总代价为
$$
\Theta(N^{\log_ba})
$$

那么我们以此为标尺，探讨根节点的代价$f(N)$和叶子层总代价$\Theta(N^{\log_ba})$的关系

1. 叶子层严格大，即叶子层主导：有$f(N) = O(N^{\log_ba-\epsilon})$ 那么结论为
   $$T(N) = \Theta(N^{\log_ba})$$

2. 根叶平衡，从而各层代价大致相等，有$f(N) = \Theta(N^{\log_ba})$，又由于层数为$\log N$（无论怎么分，最短和最长的路都必然和$\log N$同阶），从而总代价为**层数*层的代价**，即
   $$T(N) = \Theta(N^{\log_ba}\log N)$$

3. 根严格大，即$f(N) = \Omega(N^{\log_ba+\epsilon})$，总代价由根占主导，从而有
    $$T(N) = \Theta(f(N))$$
注意还有正则性定理的要求，保证下一层的总代价不会超过当前层，从而保证了**根严格大**这一设定。
